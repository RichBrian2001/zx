 # 植物个性化推荐系统运行版二开实施规范说明书

## 1. 文档定位

- 本文档是植物个性化推荐系统在当前 RuoYi-Vue 工程中的唯一实施基线。
- 后续数据库设计、菜单规划、前后端编码、页面联调、UI 完善、测试验收全部以本文档为准执行。
- 后续新增需求或范围变更，必须先修改本文档，再开始编码。
- 本文档不作为讨论稿使用，文内所有阶段、模块、页面、表、接口归属均按落地执行口径编写。

## 2. 项目目标

- 在现有 RuoYi-Vue 前后端分离项目上，完成植物个性化推荐系统的首版可演示闭环。
- 系统同时包含管理端和用户端两套页面体系。
- 管理端负责植物数据、标签、规则、内容、反馈和推荐记录管理。
- 用户端负责问卷输入、推荐结果展示、植物详情查看、历史查看和反馈提交。
- 首版推荐逻辑采用规则过滤与标签打分实现，确保可解释、可配置、可快速演示。

## 3. 首版范围边界

- 首版必须实现前后端页面、后端接口、业务表、初始化数据、推荐闭环和基础 UI 完整交付。
- 当前阶段不新建独立前台注册登录体系，但必须复用现有登录态展示真实用户 ID 与名称；推荐、历史、收藏和反馈链路不再以“匿名访客”作为对外展示口径。
- 首版不纳入商城、支付、订单、图像识别、AI 对话、自动爬虫、小程序端。
- 首版兼容 PC 管理端和手机宽度用户端页面展示。
- 首版数据允许采用人工整理数据、固定样例数据和 Excel 导入数据。

## 4. 工程实施总顺序

### 阶段 1：建立业务 SQL 表与初始化数据

- 先建立业务表结构，再建立菜单权限数据，再建立样例数据。
- 该阶段完成后，数据库必须具备基础可查数据，前后端开发不得在无表结构情况下并行乱写。
- 样例数据必须为可直接演示的真实植物数据，当前阶段固定初始化 47 条植物主数据及其配套标签、画像、规则、反馈与内容数据。
- 阶段 1 SQL 必须提供总执行入口文件，支持首次初始化和重复重跑。
- 该阶段固定输出以下 SQL 文件：
	- sql/zx_plant_demo_00_execute.sql
	- sql/zx_plant_demo_01_schema.sql
	- sql/zx_plant_demo_02_menu.sql
	- sql/zx_plant_demo_03_seed.sql
- 上述 4 份 SQL 已正式落位到项目 sql 目录，proj_plan/stage_1 保留规划说明，不再作为最终执行位置。

### 阶段 1 重跑策略

- 首次初始化或整库重装时，统一执行 zx_plant_demo_00_execute.sql。
- 仅业务表结构变更时，执行 zx_plant_demo_01_schema.sql，再执行 zx_plant_demo_03_seed.sql。
- 仅管理端菜单和权限变更时，单独执行 zx_plant_demo_02_menu.sql。
- 仅刷新演示数据时，单独执行 zx_plant_demo_03_seed.sql。
- 不允许手工挑表删数据后再混合执行脚本，统一按上述口径重跑。

### 阶段 2：冻结模块边界与页面矩阵

- 先确定系统一共有多少模块，每个模块下有哪些页面。
- 页面必须一次性规划完整，并明确哪些页面属于管理端，哪些页面属于用户端。
- 页面清单冻结后，前后端编码按页面清单逐页实现，不中途临时加散页。

### 阶段 3：编写后端业务骨架

- 先完成业务表对应的 domain、mapper、xml、service、controller 基础骨架。
- 再补充推荐引擎服务、问卷处理服务、结果解释服务。
- 所有接口命名、入参、返回结构在该阶段冻结。

### 阶段 4：编写前端页面 Demo 骨架

- 按页面矩阵完成管理端和用户端页面骨架。
- 每个页面先打通基础展示、查询、表单、详情、弹窗和路由跳转。
- 页面骨架完成后再接真实接口，不跳过页面层直接堆接口。

### 阶段 5：打通推荐主链路

- 完成问卷提交、条件解析、规则过滤、标签打分、结果排序、原因解释、结果落库、用户反馈闭环。
- 该阶段完成后，系统必须能跑通一次完整推荐演示流程。

### 阶段 6：完善 UI 与交互细节

- 管理端补齐表格操作、筛选、分页、状态展示、图片预览、表单校验。
- 用户端补齐首页引导、卡片样式、结果说明、详情布局、移动端适配。

### 阶段 7：联调与验收

- 完成数据初始化、权限校验、页面联调、演示脚本整理和最终验收。
- 验收通过后，本文档作为后续迭代基线继续维护。

## 5. 代码归属与命名规范

### 5.1 后端归属

- 业务实体、Mapper、Mapper XML、Service、ServiceImpl 放在 ruoyi-system。
- 控制器放在 ruoyi-admin。
- 管理端控制器路径统一使用 /plant/admin/*。
- 用户端控制器路径统一使用 /plant/app/*。

### 5.2 前端归属

- 管理端与用户端 API 统一放在 ruoyi-ui/src/api/plant。
- 管理端页面放在 ruoyi-ui/src/views/plant/admin。
- 用户端页面放在 ruoyi-ui/src/views/plant/demo。
- 管理端菜单走 RuoYi 动态菜单。
- 用户端页面走固定路由。

### 5.3 命名规范

- 数据库表统一使用 zx_ 前缀。
- Java 类统一使用 Zx 前缀。
- 菜单权限统一使用 plant:*:* 形式。
- 前端路由统一使用 /plant-admin/* 和 /plant-demo/* 两组路径。

## 11. 前端实施清单

### 11.1 管理端页面要求

- 所有管理端列表页必须带查询区、表格区、分页区。
- 所有管理端表单页必须带表单校验。
- 所有图片字段必须支持上传或预览。
- 所有详情页必须支持返回上一级。
- 所有管理端页面必须接入按钮权限。

### 11.2 用户端页面要求

- 首页必须具备开始推荐入口。
- 顶部导航栏必须固定包含首页、所有植物、开始问卷、植物百科问答、推荐历史、植物收藏入口，且激活态与当前绿色胶囊导航风格保持一致。
- 用户端所有对外可见标题、副标题、说明文案、按钮文案、空状态文案、提示语和介绍区文案必须使用正式运行口径，不得出现 Demo、演示、匿名访客等临时措辞；开发阶段遗留注释和调试性提示文案必须同步清理。
- 顶部右上角用户信息必须展示当前真实用户 ID 与名称，且支持点击后弹出“退出登录”操作。
- 问卷页必须支持分步或分组填写。
- 问卷页必须使用绿色主题的卡片化选项表现和明显的交互动效，不允许继续保留简化表单观感。
- 推荐结果页必须展示 Top N 结果和每个结果的推荐理由。
